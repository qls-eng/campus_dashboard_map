# 需求分析与版面设计（任务1）

## 一、业务场景选择

**场景：校园公共空间人流与出行看板（桂林理工大学雁山校区）**

选它的理由：

1. 校园场景的数据结构天然适合做多维展示——既有空间维度（建筑点位分布），又有时间维度（逐日人流变化），还有分类维度（食堂 / 教学 / 宿舍 / 运动 / 交通）。
2. 与"校园地图 + 交通信息"结合后，看板不只是画几张图，而是能回答具体问题：哪个食堂一天人最多、哪个时段学生集中、5 路公交怎么走、下雨天通勤受不受影响。
3. 数据可获得性可控：人流数据用固定种子生成后落盘保存，天气接公开接口（无密钥时自动降级），不涉及真实个人信息。

## 二、核心展示需求

| 使用角色 | 关心的问题 | 对应看板元素 |
| --- | --- | --- |
| 学生 | 现在哪个食堂/图书馆人多？公交在哪儿？ | 地图建筑圆点、建筑人流排行 |
| 后勤/管理人员 | 今天总人流多少？比昨天涨了还是降了？ | 核心指标卡（总量、平均使用率、环比） |
| 教师/访客 | 校园里各个片区怎么分布？通勤车几点发？ | 地图、类型占比饼图、通勤车时刻弹窗 |
| 数据分析视角 | 哪类建筑承载了主要人流？ | 各类型人流量对比柱状图 |

一句话概括需求：**在一个页面内同时回答"总量多少、分布在哪、结构如何、趋势怎么走"四个问题**。

## 三、四大模块划分

按指导书要求，把页面切成四个区域：

| 模块 | 位置 | 内容 | 承担的图表类型 |
| --- | --- | --- | --- |
| 数据概览区 | 页面最上方 | 总人流量、平均使用率、峰值建筑、监测建筑数，外加一行实时天气摘要 | 数据卡片（metric） |
| 维度统计区 | 中部左侧 | 各建筑类型人流量合计（分类对比）、建筑人流排行（横向条形） | 柱状图 / 条形图 |
| 趋势分析区 | 中部右侧 + 下沿 | 未来 24 小时温度与降水量双轴折线 | 折线图 |
| 明细数据区 | 下半部右侧 | 人员活动结构环形饼图 + 建筑明细表 | 饼图 / 数据表 |

地图区单列在中部，作为空间维度入口，横跨整行（`layout="wide"` + `height=600`）。

## 四、配色方案

| 角色 | 亮色模式 | 暗色模式 | 用途 |
| --- | --- | --- | --- |
| 主色（primary） | `#1f77b4` | `#4a9eff` | 指标卡左侧竖条、主折线、主柱 |
| 辅助色（secondary） | `#ff7f0e` | `#ff9f4a` | 公交线路、对比强调 |
| 背景色（bg） | `#f5f7fa` | `#1a1a24` | 页面底色 |
| 卡片底色（card） | `#ffffff` | `#2a2a35` | 指标卡、侧边栏 |
| 正文色（text） | `#2c3e50` | `#e0e0e0` | 标题与正文 |

建筑类型固定配色（保证同一类型在饼图、柱图、地图上颜色一致）：学习 `#1f77b4`、餐饮 `#ff7f0e`、住宿 `#2ca02c`、运动 `#d62728`、服务 `#8c564b`、活动 `#e377c2`、出入口 `#7f7f7f`。

使用率作为"预警"维度单独给一套色阶：蓝（< 60%）、橙（60% ~ 85%）、红（≥ 85%），只在地图圆点上使用，避免与类型配色混淆。

## 六、图表选型理由

| 数据特征 | 选用图表 | 理由（为什么不用别的） |
| --- | --- | --- |
| 4 个天气标量 | 强调卡片（绿色、大字号、置顶） | 天气是"实时外部输入"，与内部统计不同源，需要视觉上区分出层级，不能和核心指标混在一起 |
| 4 个标量核心指标 | 数据卡片 | 单值指标用卡片最直观；用柱图会浪费空间 |
| 7 类建筑的人流合计 | 柱状图 | 分类数量少、要对比"谁高谁低"，柱图排序后一眼可读；折线图不适用（无时间轴） |
| 17 个建筑的人流排序 | 横向条形图 | 类目名称较长（"一号组团宿舍"），横向条形能放下标签且长度对比直观 |
| 使用率均值（单个 0~100 百分比） | 仪表盘 | 单值 + 有阈值含义（过低预警、过高拥挤），圆环三段配色比纯数字更快传达"健康度" |
| 24 小时温度与降水 | 双轴折线 | 两条量纲不同的序列（℃ 与 mm）需要共享时间轴，双轴折线最合适；用两个图会割裂相关性 |
| 24 小时人流分布（两日对比） | 双折线 | 需要同时看出"峰在几点"和"两日强弱差"，两条线同轴叠放成本最低 |
| 类型占比 | 环形饼图 | 结构问题（"食堂占多少"）用饼图；环形留中空可放说明文字 |
| 明细核对 | 数据表 | 需要精确数值和排序时表格不可替代 |

## 七、数据维度整理

| 维度类型 | 字段 | 说明 |
| --- | --- | --- |
| 时间维度 | `日期` | 2026-11-17 / 2026-11-18 两天，用于算环比增长率 |
| 分类维度 | `建筑名称`、`类型` | 17 个点位、7 种类型 |
| 数值维度 | `人流量`、`使用率(%)` | 卡片总量、柱图高度、饼图占比、地图圆点大小 |
| 空间维度 | `经度`、`纬度` | 仅地图使用，由 `data/mock.py` 提供 |

## 八、明确不做的事（范围控制）

1. 不做登录与权限，不做真实门禁数据接入（涉及个人信息）
2. 不做数据库，数据落成 CSV 即可，方便助教直接打开核对
3. 不做实时流式推送（扩展任务范畴），天气按请求时拉取
4. 不强制要求地图 API 密钥：无密钥时退回手工站点连线，保证"克隆即可运行"
